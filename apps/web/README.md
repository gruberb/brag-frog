# Brag Frog web

React 19 SPA for Brag Frog. It talks to the Axum JSON API under `/api/v1` with the same session cookie, so there is no CORS and no token handling in the browser.

Stack: Vite 7, React Router 7, TanStack Query 5, Tailwind v4 (`@theme` tokens), Radix, react-hook-form + zod, BlockNote (lazy, Review only), `@react-pdf/renderer` and `docx` (lazy, on download).

## Commands

Run from the repo root with moon, or from `apps/web` with npm.

| Task | moon | npm |
|---|---|---|
| Dev server (proxies `/api /auth /custom /healthz` to `localhost:8080`) | `moon run web:dev` | `npm run dev` |
| Dev server with in-memory MSW data, no backend | | `npm run dev:mock` |
| Lint (ESLint, includes import boundaries) | `moon run web:lint` | `npm run lint` |
| Typecheck | `moon run web:typecheck` | `npm run typecheck` |
| Tests (Vitest + Testing Library + MSW) | `moon run web:test` | `npm run test` |
| Production build to `dist/` | `moon run web:build` | `npm run build` |

`BRAGFROG_API_URL` overrides the proxy target (default `http://localhost:8080`).

`dev:mock` starts the MSW service worker (`public/mockServiceWorker.js`, removed from production builds) with the stateful handlers in `src/testing/mocks`. The same handlers back the tests, so mock data and test data cannot drift.

## Structure

```
src/
  app/          main, provider, router, routes/* (composition of features), command palette
  components/   ui/ (Button, Drawer, Dialog, ...), layout/AppShell, editor/ (BlockNote, lazy)
  config/       paths, env
  features/     auth cycles entries integrations logbook priorities review settings today trends
  hooks/ lib/ stores/ testing/ types/ utils/
```

Rules (enforced by `import/no-restricted-paths`, proven by `src/testing/architecture.test.ts`):

- Flow is one way: shared (`components hooks lib stores types utils config`) then `features` then `app`.
- A feature never imports another feature. Routes in `src/app/routes` compose features and pass slots as props or components (for example the evidence picker and entry drawer into the Review page, the quick composer into Today).
- No barrel files. Query keys live next to each feature's `api/` code. `src/types/api` is for generated types.

## Look and feel

Tokens in `src/app/app.css` are the values the app has always used (`@theme static`, so `/custom/tokens.css` can still override them; that link sits after `#root` in `index.html` to win the cascade). Mozilla Headline and Mozilla Text are copied to `public/fonts`. Body uses `--font-stack`, headings `--font-stack-heading`, form controls use `font: inherit`. `src/app/shell.test.tsx` fails if any other `font-family` appears in UI code (PDF and DOCX output uses IBM Plex Sans, since react-pdf cannot embed WOFF2 variable fonts).

## API contract

Types are the ts-rs files generated by `apps/api` into `src/types/api/` (never edited by hand). `src/types/api/models.ts` only re-exports them under short UI names and holds the few client-only types (`EntryFilters`, `ContentFormat`); `client.ts` has the shared error body. The MSW backend in `src/testing/mocks` is typed with the same DTOs, so a contract change fails compilation there first.

How the UI maps onto the API where the two differ from the original plan:

- **Entries:** the list returns full `EntryDto` rows. `PUT /entries/{id}` replaces the editable fields, so the drawer always sends all of them; empty optional fields are omitted. Filters use `category` (a slug from `worklog::model::CATEGORIES`; the dropdown lists only the ones in `GET /entries/facets` `categories`, which have entries in the cycle) and `no_priority | no_team | no_person`. Entry types for the form come from `GET /meta/entry-types`. The old "outcome" field and a bulk "type" change are gone because the API has no field for them; bulk edit supports priority, reach, complexity, role and appended teams. There is no "needs classify" view.
- **Reports:** a report is built from the same filter keys as the entries list (`LogbookFilter`), so the dialog sends the active filters unchanged.
- **Cycles:** `POST /cycles` makes the new cycle the active one; `/activate` switches back to another. The Logbook total comes from `/entries/facets` (`total`).
- **Today:** meetings carry `has_prep`; prep is `GET/PUT /meetings/{id}/prep` with `{ entry, note }`. Focus time is `focus_minutes`.
- **Priorities:** statuses and tracking values are plain strings (`on_track`, `off_track`, ...). Active in the UI means `active | not_started | on_hold`, Done means `completed | cancelled`. The Lattice import posts the CSV as multipart `csv_file` with `cycle_id` in the query string.
- **Review:** sections come with `content` (nullable) and `content_format` (`markdown` for old text, `blocknote` after the first save). Jira key links use the `atlassian` service `base_url` field from `/config`.
- **Settings:** the profile is `UserDto` and is replaced on save (empty string clears). People `POST` returns the whole list. The Anthropic key is the `claude` integration (`token_only`), managed on the AI tab and hidden from the Integrations tab.
- **Integrations:** the configure drawer renders `fields` from the API (`text` or `checkbox`; names are `IntegrationInput` keys). Google services (`oauth_connect`) need no token. Saving tests the connection on the server; the first sync is started with `POST /sync/{service}`. Status is derived from `is_enabled` and `last_sync_status`. Sync status is polled every 2 s while `running`, every 60 s otherwise, never in a hidden tab.
- **Trends:** The top row is the API's `kpis`: docs created, PRs opened, reviewed and merged, meetings, tickets opened and closed. The weekly chart stacks `by_category`, one series per category (`features/trends/utils/categories.ts`). Bars drill down into the Logbook by week, person, team, category or repository search.
- **Cycle bundle** (`GET /cycles/{id}/bundle`): review sections, priorities with `timelines`, and entries grouped by ISO week.

## Notes for later milestones

- First load for `/today` pulls zod through the entry form. If the 200 KB gzip budget in M5 is tight, the entry form can move behind a dynamic import.
- Editor chunk (`RichEditor`) loads only on `/review`; PDF and DOCX chunks load only when a download starts.
